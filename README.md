# TEMPOLIVE 連線節拍器

為教會敬拜團、現場樂團與音控同工設計的網頁節拍器。從個人練習、事先編排歌單，到主持人統一控制團隊節奏，都可以在同一個頁面完成；加入房間後，還能透過 **live傳話** 快速向指定樂器發送語音提醒。

**單一 HTML · 繁體中文 · 四位數字房間 · 歌單保存 · 樂器語音傳話**

本文對應版本為 **v1.17**，以 [`TEMPOLIVE-v1.17.html`](./TEMPOLIVE-v1.17.html) 的實作為準。部署章節屬於額外操作指引，不是程式內建的自動部署功能。

> **使用定位**
>
> 個人節拍器與小遊戲可在檔案載入後離線使用；團隊房間與 live傳話需要網路，目前連接公開測試中繼。網路校時不等於耳機實際出聲完全同步，正式演出前務必使用現場裝置、耳機與網路測試。本專案不承諾零延遲、訊息必達或不中斷。

## 開始使用

### 個人練習

1. 下載 `TEMPOLIVE-v1.17.html`，用瀏覽器開啟，不需要安裝套件或執行建置指令。
2. 設定 BPM、拍號、音符細分及拍點，按下 **「開始節拍」**。
3. 從主畫面調整本機音量；音色、輸出強度與其他選項都在右上角 **「設定」**。

請在完整瀏覽器中開啟，而不是只在通訊軟體的檔案預覽中使用。直接開啟本機 HTML 的儲存與權限行為依瀏覽器而異；固定部署網址更適合長期保存設定，詳見「資料保存」與「部署」。

### 團隊使用

1. 主持人按 **「建立房間」**，選擇自己的樂器／角色，建立後將四位數字代碼交給團員。
2. 團員開啟相同版本，按 **「代碼加入」**，選擇樂器／角色並輸入代碼。
3. 完成連線與校時後，由主持人控制節拍。要使用語音傳話，請每台裝置先完成 **「試聽語音」**。

所有裝置都需要可連線的網路，並使用相同的中繼設定與版本。藍牙只負責各裝置的聲音輸出，**不是建立房間的方式**。

## 節拍器操作

### 速度、拍號與預備拍

BPM 範圍為 **40–300**。可直接輸入後按 Enter／完成輸入，使用 `＋／－`、拖曳滑桿，或連續點選「點按測速」。

支援拍號：**2/4、3/4、4/4、5/4、6/8、7/8、12/8**。

**本專案的 BPM 固定以四分音符為基準。** 四分、八分、十六分音符分別在一個四分音符的時間內發聲 1、2、4 次；`/8` 拍號的拍點則依八分音符計數。例如樂譜標示「附點四分音符 = 70」，在此應設定為 **105 BPM**。

點選拍點會依序切換：

**重音 → 一般 → 靜音 → 重音**

預備拍可選擇關閉、1 小節或 2 小節，從停止狀態開始播放時生效。

### 哪些調整立即生效？

| 操作 | 播放中的套用方式 |
| --- | --- |
| BPM、點按測速、拍點重音、音符細分 | 立即更新，不排到下一個小節；已交給裝置輸出的聲音無法回收或重播。 |
| 拍號等一般節奏設定 | 依現有預留時間，安排在拍點交界套用。 |
| 選擇歌曲、前一首、下一首 | 在預告的小節交界套用，避免切斷當前小節。 |
| 本機音量、音色、輸出強度 | 只改變目前裝置，不修改團隊節奏。 |

開始播放與房間同步仍有音訊排程及網路預留時間。「立即更新」不代表移除瀏覽器、藍牙或網路的物理延遲。

### 操作入口與快速鍵

主畫面提供「下一首、開始／停止、點按測速」，音量與靜音也留在主畫面。歌曲清單另有前一首與下一首。

右上角依序為 **專注模式、疑問教學、節奏小遊戲、設定**。

| 按鍵 | 功能 |
| --- | --- |
| 空白鍵 | 播放／停止；房間參與者依目前狀態執行本機靜音、恢復收聽或恢復聲音。 |
| `T` | 點按測速。 |
| `N` | 下一首。 |
| `↑`／`↓` | BPM 增減 1；搭配 Shift 增減 5。 |
| `F` | 切換專注模式。 |

輸入文字、操作表單或開啟對話視窗時，不套用一般主畫面快速鍵。按鈕使用 `touch-action: manipulation`，降低手機連續點按時觸發雙擊放大的情況，沒有全面禁止頁面縮放。

## 歌曲清單與切歌規則

### 建立、更新與切換歌曲

按「新增歌曲」，填入歌名、BPM、拍號、音符細分與預備拍，再按 **「儲存歌曲」**。已有歌曲可從編輯按鈕修改、調整順序或刪除。

主畫面的臨時調整，與歌單內的歌曲預設分開管理。要把當前調整寫回某首歌曲，使用：

**儲存目前設定 → 確認歌曲資料 → 儲存歌曲**

直接點歌名、前一首、兩個下一首按鈕與 `N` 快速鍵，都使用相同的切歌流程。前後首依歌單順序循環。

### v1.17：切換歌曲不重設輕重音

**下一首會載入該首的歌名、BPM、拍號、音符細分與預備拍，但沿用目前的輕重音配置。**

| 目前拍點 | 切換到不同拍數後 |
| --- | --- |
| 全部重音 | 新歌曲所有拍點仍為重音。 |
| 全部一般拍 | 新歌曲所有拍點仍為一般拍，不會把第一拍改回重音。 |
| 全部靜音 | 新歌曲所有拍點仍為靜音。 |
| 混合重音、一般與靜音 | 保留各拍位置；拍數縮短時，隱藏位置仍記住。拍數增加時恢復既有設定，從未設定過的位置使用一般拍。 |

例如：`重、一般、靜音、重` 從四拍換成三拍，顯示 `重、一般、靜音`；之後換回四拍，仍恢復原本的第四拍重音。

輕重音延續資訊以 `accentCarry` 保存在本機。它不會批次改寫歌單中已存好的歌曲。歌曲資料仍可包含 `accents`，但正常切歌時以目前的輕重音延續設定為準，而不是重新載入該首的重音預設。

### 匯入、匯出與範例

歌單上限為 **200 首**，歌名最多 **40 字**。匯入接受本程式匯出的 JSON，檔案大小上限為 **2,000,000 bytes**；確認後會**取代目前整份歌單**，不是追加合併。

匯出檔名格式為 `metronome-setlist-YYYY-MM-DD.json`，包含歌曲及各首設定，不包含整台裝置的所有偏好。

內建三筆可編輯、可刪除的範例：

| 範例名稱 | BPM | 拍號 | 音符細分 | 預備拍 |
| --- | --- | --- | --- | --- |
| 開場讚美 | 120 | 4/4 | 八分音符 | 關閉 |
| 安靜敬拜 | 72 | 4/4 | 四分音符 | 關閉 |
| 回應詩歌 | 96 | 6/8 | 八分音符 | 1 小節 |

這些是示範資料，不代表任何特定歌曲的標準速度。

## 團隊房間

房間使用 **MQTT 3.1.1 over WSS** 交換控制資料，由各裝置在本機產生節拍聲，**不是串流主持人的音訊**。目前不使用 PeerJS、WebRTC、STUN 或 TURN。

### 主持人與團員的權限

| 操作 | 主持人 | 團員 |
| --- | --- | --- |
| 控制共同播放／停止、BPM、拍號、細分與重音 | 可以 | 跟隨主持人 |
| 切換團隊目前歌曲 | 可以 | 跟隨主持人 |
| 調整自己的音量、音色、時間校正 | 可以 | 可以 |
| 使用 live傳話 | 可以 | 可以 |
| 調整自己的外觀、閃爍與語音偏好 | 可以 | 可以 |

房間最多 **12 人，包含主持人**。分享的是目前歌名、節奏與播放狀態，**不會同步或覆蓋團員的整份歌單**。

### 校時與連線狀態

程式以往返探測估計裝置時差，加入房間、重新連線與手動按「重新校時」時會取樣。參與者在前景且連線開啟時，也會約每 60 秒集中重新取樣。

主持人的啟動預留時間會參考團員的往返延遲；已有有效樣本時限制在 0.6–1.6 秒，沒有樣本時使用 0.85 秒。畫面顯示的往返延遲是網路資料，**不是耳機實際出聲誤差**。

偵測到中繼斷線時，程式會停止本機排程並嘗試重新連線。主持人結束房間或連線無法維持時，團員會停止跟隨；目前沒有主持人轉移功能。請保持頁面在前景，勿把鎖定螢幕後持續播放視為保證功能。

## live傳話

**加入或建立房間後**，右側才會出現固定於螢幕側邊的「live傳話 NEW」控制鈕；離開房間後隱藏。

### 操作流程

**開啟 live傳話 → 選對象 → 點短句 → 自動送出並收起面板**

不需要再按傳送確認，也不要求對方回覆「已收到」。選錯對象可按「換對象」返回；重新開啟面板會從選對象開始。

可指定房間內的某個樂器／角色，或「全部人」。「全部人」包含其他團員與適用的主持人，但不包含發送者自己。同一樂器有多人時，以「鋼琴 1」「鋼琴 2」等編號區分，傳送仍依裝置識別碼定位。

建立或加入房間可選擇：

**鋼琴、鍵盤、木吉他、電吉他、貝斯、鼓、主領、歌唱、音控**

另可新增樂器／角色，名稱最多 16 字，本機最多保留 12 個自訂項目。

### 短句與實際播報

| 點選的方塊 | 語音中的指令 |
| --- | --- |
| 太快 | 慢一點 |
| 太慢 | 快一點 |
| 多一點 | 多一點 |
| 少一點 | 少一點 |
| 監聽大 | 監聽大一點 |
| 監聽小 | 監聽小一點 |
| 要幫忙 | 需要幫忙 |

例如：鼓選擇「鋼琴」與「太慢」，會播報 **「鼓手說，鋼琴，快一點。」**

自訂訊息最多 40 字，輸入後按 Enter 或點下方文字方塊送出。勾選「儲存為本機常用短句」後，下次可直接點用；最多保留 12 則常用短句。

### 語音與接收方式

先在建立／加入房間時按「試聽語音」，或展開傳話面板下方的 **「語音與常用短句」→「啟用／試聽」**。這裡可調整自動播報、語音音量與中文聲音。

接收方會顯示文字通知，符合語音啟用條件時自動播報，也可按「再播一次」。內部仍有去重、重試與到達確認機制，但不顯示接收進度或已讀回報，也不能因此確認對方真的聽清楚。

訊息自動播報時限為 20 秒；過時訊息不會自動補唸。待播語音會排隊，不直接疊加播放；每次發送間隔至少 700 毫秒。

**傳話程式不會主動暫停、重啟或調低節拍器。** 不過系統語音與 Web Audio 是否能在同一裝置穩定同時輸出，仍需實測；若系統造成節拍音訊中斷，程式會停止語音並提示處理，不保證所有手機都能無縫混音。

## 音訊、藍牙與視覺設定

### 三組音量分開控制

| 聲音 | 調整位置 | 初始值 |
| --- | --- | --- |
| 節拍器 | 主畫面的「本機音量」 | 70% |
| live傳話 | 傳話面板內「語音與常用短句」 | 100% |
| 節奏小遊戲 | 遊戲面板的「遊戲音量」 | 100% |

三者都可調至 0%，但不會互相修改；實際輸出也受到系統媒體音量與硬體限制。

右上角「設定」提供 **木塊、清晰電子、牛鈴、短鈴、馬林巴**五種音色，預設為馬林巴。輸出強度只有「標準」與「加強」；「加強」沿用較高發聲密度的設定，不會提高手機喇叭的硬體功率。使用耳機請先降低音量再逐步調整。

### 輸出裝置與時間校正

未接耳機時可使用手機喇叭；藍牙耳機請先在作業系統完成配對並選擇輸出。瀏覽器支援時可從網頁選擇音訊裝置，不支援時改由系統切換。

本機時間校正範圍為 **−300 至 +300 毫秒**，每次 5 毫秒。聲音比其他人慢可往負值調整，太快則往正值調整。自動延遲估計使用瀏覽器回報值，不等於實際聲學量測。

live傳話使用系統語音輸出，**不會自動跟隨節拍器在網頁內另選的音效卡**。請在節拍播放期間測試語音，確認兩者都從預期的喇叭／耳機出聲。

正常播放與傳話不需要錄音。只有在選擇音訊裝置、且瀏覽器要求先取得裝置名稱時，程式可能請求麥克風權限；該流程會在結束時停止取得的音軌，不錄音、不傳送麥克風聲音。

### 深色模式與螢幕閃爍

「螢幕閃爍 NEW」位於深色模式下方，預設關閉。開啟後只在節拍器區塊內發光：淺色模式為黑色、深色模式為白色，每次約 0.32 秒並逐漸淡出。

高速度時會減少閃爍次數，兩次起始至少間隔 350 毫秒，不會跟著所有細分音符高速閃動。靜音拍不發光；主音量靜音時仍可保留有聲拍的視覺提示。開啟小遊戲、頁面進入背景或停止節拍時，不顯示這項光效。

對閃光敏感者請保持關閉；頻率限制不是醫療安全保證。

## 節奏小遊戲

點選右上角 **遊戲圖示 NEW**，即可開啟「節奏記憶挑戰」。先聽系統示範，再在音符隱藏後按「敲一下」或空白鍵重現節奏。**示範時按鍵不會自動閃動**，玩家敲擊的回饋仍保留。

共有 **10 關、3 次失誤機會**，每題 4 拍，BPM 從第 1 關的 75 逐步增加至第 10 關的 120。準確率達 95% 即通關，每過一關累計分數加 10 分；失敗但仍有機會時，重試同一道題目。

| 操作 | 行為 |
| --- | --- |
| 遊戲內「暫停」→「繼續本關」 | 重新開始當前關卡的相同題目。 |
| 「返回節拍器」後再開啟 | 保留目前頁面中的遊戲進度；按「繼續遊戲」才恢復聲音與計時。 |
| 重新開啟時選「重新遊玩」 | 從第 1 關、0 分、3 次機會重來，保留最高分與遊戲音量。 |
| 重新整理或關閉整個網頁 | 不保存未完成的一局；僅最高分與遊戲音量有本機儲存處理。 |

遊戲使用自己的音訊環境與鍵盤事件，不會控制主節拍器。如果主節拍器仍在播放，遊戲只會提醒，不會替使用者停止；避免兩組節奏混在一起時，請先自行停止或靜音本機節拍。

## 資料保存與備份

### 哪些資料會保留？

主程式會保存歌單、歌單順序、目前選擇的歌曲與節奏，以及音量、音色、輸出強度、深淺色、時間校正與螢幕閃爍等偏好。v1.17 也保存輕重音延續資訊，包含因縮短拍數而暫時隱藏的位置。

v1.16 起，歌曲儲存、排序、刪除與匯入採立即寫入；一般操作保留短暫合併存檔，頁面切入背景、凍結或離開前再補存。瀏覽器拒絕寫入時會提示，不能將當次頁面中的資料視為已永久保存。

| 儲存位置 | 內容 |
| --- | --- |
| `tw.metronome.v1` | 歌單、目前節奏、`accentCarry`、選曲與節拍器偏好。 |
| `tempolive.band.v1` | 樂器／角色、自訂樂器、常用短句、語音音量與聲音偏好。 |
| `tw.metronome.rhythm-game.volume.v1` | 遊戲音量。 |
| `rhythmMasterHighScoreV2` | 遊戲最高分，由遊戲 iframe 的儲存環境處理；無法存取時有記憶體備援。 |

房間連線、播放中的狀態、未完成的一局，以及傳話收發紀錄不會作為下次開啟的持久歷史還原。本機靜音狀態也不會以「保持靜音」保存。

### 同一台裝置，不代表同一份儲存空間

`localStorage` 依瀏覽器與網站來源區分；無痕模式、清除網站資料、切換瀏覽器或網站來源，都可能讓原設定無法沿用。直接以 `file:` 開啟的檔案，其儲存行為沒有跨瀏覽器的一致保證；換檔名或位置時尤其不要假設舊資料會自動搬過來。[1]

升級版本前，先在舊版 **「匯出歌單」**。新版若讀不到舊歌單，再匯入一次。固定使用相同瀏覽器與網站來源，並保留一份匯出備份。

**匯出歌單不是完整設定備份。** 它不包含獨立的 `accentCarry` 隱藏位置記憶、語音偏好、自訂樂器、遊戲最高分或所有裝置設定；這些資料目前沒有統一的匯入／匯出功能。

## 使用限制與隱私

目前程式設定連接 shiftr.io 公開測試中繼。四位代碼是邀請碼，**不是安全密碼**；房間沒有帳號登入、加入審核或端對端加密。

中繼會經手樂器／角色、目前歌名、節奏、播放狀態與傳話文字；指定傳話經主持人轉送。請勿使用敏感歌名、真實身分資訊或機密內容。WSS 加密傳輸不代表訊息對中繼服務或主持人不可見。

程式優先選擇可用的中文／本機語音，但裝置提供的某些聲音可能需要網路，文字也可能由該語音服務處理。是否真的從耳機播出，仍需由使用者試聽確認。

| 限制 | 使用時的處理方式 |
| --- | --- |
| 公開中繼無服務可用率承諾 | 正式或關鍵演出應另行配置可控中繼，並測試實際環境。 |
| 藍牙與裝置延遲不同 | 優先測試有線監聽；必要時使用各裝置的本機時間校正。 |
| 背景、鎖定螢幕、系統中斷可能影響聲音 | 保持頁面前景，使用支援時的螢幕保持開啟功能，預留恢復操作。 |
| 語音與節拍不一定能穩定同時輸出 | 排練時測試；不支援時改用文字通知，不把播報狀態當成已聽到。 |
| 單人功能可離線，不代表整個產品全離線 | 房間與傳話需要網路；語音合成本身也可能依賴外部服務。 |

目前沒有內建帳號系統、雲端歌單備份、跨裝置偏好同步、離線安裝套件或主持人自動移交功能。

## 常見問題

### 沒戴耳機就沒有聲音，或返回網頁後突然無聲？

先確認系統媒體音量、主畫面音量及輸出裝置，避免聲音仍送到藍牙耳機。可到設定按「試聽音色」。

房間參與者若出現 **「恢復本機聲音」**，點中央按鈕恢復；音量旁的按鈕也保留恢復操作。程式會重建本機音訊環境，再跟上原本節奏，不是重新開始整個房間。恢復提示是預防性的狀態判斷，不是實際偵測喇叭是否有聲。

### 加大音量後，現場仍聽不清楚？

確認選到「加強」且系統與網頁音量沒有被降低。程式能調整數位訊號，但不能增加手機喇叭的物理功率。不要以耳朵不舒服作為足夠音量的標準；需要時接到適當的監聽系統。

### 為什麼切歌後不是那首歌原本儲存的重音？

這是 v1.17 的預期行為：切歌沿用目前拍點，避免現場已設定好的全重音、全一般拍或混合配置被重設。要改變目前配置，直接點選拍點。

### 加入房間一直失敗？

確認全員使用同一版、代碼正確、主持人未關閉頁面，且中繼網址與命名空間一致。可改用另一個 Wi-Fi 或手機熱點測試；網路政策與公開服務狀態都可能影響連線。

`R10` 表示已連到中繼但找不到房間，`R11` 為整體連線逾時，`R12` 為校時未能完成。回報問題時保留完整錯誤碼與訊息。

### live傳話收到文字，卻沒有語音？

在「語音與常用短句」按「啟用／試聽」，確認自動播報開啟、語音音量不為零，並有可用中文聲音。檢查系統輸出，而不只是節拍器的音效卡選擇。已過播報時限的訊息不會自動補唸，可按「再播一次」。

### 重新開啟後歌單不見了？

先確認是否換了瀏覽器、無痕視窗、檔案位置或網站來源。若出現儲存失敗提示，請在仍有資料的頁面立即匯出歌單。程式沒有伺服器端備份，不能保證從已被清除的瀏覽器資料中復原。

## 技術架構

程式採 **HTML、CSS 與原生 JavaScript**，節拍音色由 Web Audio 產生。所有介面、SVG 與小遊戲來源都包在同一個 HTML，不需要 npm、前端框架、外部音檔或額外的遊戲檔案。

| 模組 | 主要內容 |
| --- | --- |
| 主節拍器腳本 | `CONFIG`、`TEXT`、`SAMPLE_SONGS`、`AudioEngine`、節奏時間軸、歌單、本機儲存與畫面設定。 |
| 輕重音延續 | `accentCarryFrom()`、`fitAccentCarry()`、`rememberLiveAccents()` 與 `keepAccents` 切歌選項。 |
| 房間傳輸 | `MqttWire`、`RelayPeer`、`RelayConnection` 與 `Room`，使用版本化節奏快照及四時間戳校時。 |
| 小遊戲 | `rhythmGameSource` 內的 JSON 字串，開啟時載入 iframe；`rhythmIntegration` 處理收起、主題與音量。 |
| live傳話 | `band-addon-script`，擴充房間成員資訊與 `band-*` 訊息，使用系統語音合成。 |

音訊排程由約 25 毫秒的 Worker 喚醒；不支援時使用計時器備援，再把聲音安排到音訊時鐘。畫面動畫由 `requestAnimationFrame` 更新，沒有把 JavaScript 計時器回呼直接當成精準發聲時刻。

### 中繼設定

修改 `CONFIG.relay` 可指定部署環境。以下為 v1.17 原始設定中的連線欄位，**不是已通過現場驗證的服務保證**：

```js
relay: {
  url: 'wss://public.cloud.shiftr.io',
  username: 'public',
  password: 'public',
  namespace: 'tw-metronome-202609-v2',
  connectTimeout: 8500,
  requestTimeout: 7000,
  maxReconnects: 2
}
```

以上帳密是目前檔案中的公開測試設定，不是私密憑證。改用專用服務時，所有裝置必須使用相同設定；不要把私密、長期且具高權限的服務憑證直接放進公開 HTML。

調整重試策略時應一併檢查實際連線流程，不能只憑設定欄位名稱推定每個重試路徑都受其控制。

### 診斷資料

可在瀏覽器開發者工具的 Console 讀取：

```js
MetronomeDiagnostics.snapshot()
MetronomeGameDiagnostics.snapshot()
TempoliveBand.snapshot()
```

分別提供節拍器／房間與本機儲存狀態、遊戲狀態、live傳話狀態。回報前先移除房間代碼、樂器身分及訊息內容等不需要公開的資料。

**HTML 發布版號、儲存格式版本與各子模組的診斷版本不是同一件事。** 例如主儲存格式維持 `version: 1`，不表示程式仍是初版；子模組可能保留原本的版本標記。

## 部署

以下是部署操作指引；目前 HTML 不會自行建立 GitHub 儲存庫或發布網站。

### 保留原始檔的專案結構

```text
TEMPOLIVE/
├── README.md
└── TEMPOLIVE-v1.17.html
```

直接測試不需要其他檔案。對外發布時，可另外將使用中的 HTML 複製成 `index.html` 作為入口，仍保留版號檔方便比對：

```text
TEMPOLIVE/
├── README.md
├── index.html
└── TEMPOLIVE-v1.17.html
```

`index.html` 必須是完整的節拍器 HTML，不是把 README 內容改名。

### 發布到 GitHub Pages

GitHub Pages 可發布 HTML、CSS、JavaScript 靜態網站。[2] 本案不需要自訂前端建置流程：

1. 將 `README.md`、正式使用的 `index.html` 及需要保留的版號檔放入儲存庫。
2. 在儲存庫的 **Settings → Pages → Build and deployment** 選擇 **Deploy from a branch**，指定實際存放檔案的分支與 `/(root)`。
3. 儲存並等候發布完成，使用 Pages 顯示的網站網址測試。[3]、[4]

主機只負責提供網頁檔案；**房間中繼仍是 `CONFIG.relay` 設定的外部服務**，不會因為部署到 GitHub Pages 就自動更換成 GitHub 的同步服務。

更新時保持入口名稱固定，替換為新版本完整內容，並通知團員重新載入。即使網址不變，升級前仍應先匯出歌單備份。

## 維護原則與驗收

這個專案以現場快速操作為優先。維護時只修改指定範圍，保留未提及的功能與設定；新增功能的入口應加上 **NEW** 標示，並保持深淺色一致。

不要因為介面精簡而移除未注意到的音訊恢復、校時、按鍵權限或本機資料保存流程。修改儲存格式前要處理舊資料相容性；也不要把內部「送達／完成播報」當成使用者實際聽到。

**以下是每次修改後的驗收清單，不是本文件宣稱已在所有裝置測試通過的紀錄：**

- [ ] BPM 上下限、連續加減、點按測速、音符細分及播放／停止正常，停止後沒有殘留音效。
- [ ] 全重音、全一般拍與混合配置跨不同拍數切歌後仍符合 v1.17 延續規則。
- [ ] 歌單儲存、排序、重新開啟、匯入／匯出與儲存失敗提示正常。
- [ ] 主持人與團員能建立／加入、校時、斷線處理；團員無法更改共同節奏。
- [ ] live傳話指定／全體、自訂訊息、語音音量及文字備援正常，並在實體裝置測試與節拍同時輸出。
- [ ] 小遊戲繼續／重玩、獨立音量、示範不閃 TAP，以及主節拍器互不干擾正常。
- [ ] 手機與電腦版面、深淺色、區塊閃爍、鍵盤操作及系統輸出切換正常。

### 本版重點

**v1.17**：切換歌曲或拍數時保留目前輕重音，混合配置的隱藏拍點也會記住，不批次覆寫歌曲資料。

**v1.16**：移除主畫面上方重複的恢復聲音說明，保留實際恢復操作；補強歌單立即儲存與離開前補存。
